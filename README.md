# rootfs-diff

A lightweight, build-system-independent firmware release reviewer, available as a Go library and CLI.

Compare two complete rootfs tar or tar.gz artifacts from Buildroot, Yocto or any build system that produces supported rootfs archives. rootfs-diff reads recorded files and metadata without extraction or target execution, then writes deterministic text, JSON or Markdown reports.

Review removed paths, content hashes, numeric ownership, permissions, link targets and device metadata. Add your own required-path or net payload-growth rules to gate a release in CI. Ordinary differences succeed unless an enabled check fails.

## Buildroot release review

The [executed Buildroot proof](examples/buildroot/README.md#observed-execution) compares two archives generated by Buildroot, with independent inspection of every recorded entry. Follow the [pinned recipe and reproduction commands](examples/buildroot/README.md#prerequisites-and-reproduction) to repeat it.

**Verified summary of the actual CLI results** (canonical root-relative paths):

| Recorded path | Controlled change |
|---|---|
| `etc/init.d/S40network` | Removed |
| `etc/device.conf` | Mode `0640` to `0666` |
| `usr/bin/device-agent` | Symlink target `agent-v1` to `agent-v2` |
| `usr/lib/libexample.so` | Grows by 420 KiB (430,080 bytes) |

There is one removal, three modifications, no additions and no metadata warnings. The 430,080-byte file increase minus the removed 17-byte startup script gives **430,063 bytes of net regular-payload growth**. These are uncompressed payload bytes, not flash or download size.

The images contain controlled demo payloads: `S40network` and the agent endpoints are stubs, and `libexample.so` is a fully written zero-filled file. No target content is executed or booted.

To require that startup path, save this user-defined, required-path-only policy as `required-paths.json`. It enables no growth budget. Report and policy paths are canonical and root-relative:

```json
{
  "schema_version": 1,
  "required_paths": ["etc/init.d/S40network"]
}
```

```sh
./bin/rootfs-diff --policy required-paths.json before.tar after.tar
```

On the real archive pair, this policy returns **1 with a complete report** and one `required_path` violation. The [full proof's gated report](examples/buildroot/README.md#observed-execution) uses both required presence and a 409,600-byte net-growth budget, so it shows two violations. Without a gate, ordinary differences return 0. Invalid input or an operational failure returns 2; output may be incomplete. See the [status-preserving CI example](docs/ci.md).

## Install and quickstart

Download [v0.1.0 binaries and checksums](https://github.com/Azhovan/rootfs-diff/releases/tag/v0.1.0) for Linux or macOS on amd64/arm64, or build from source with Go **1.27.4** (module minimum **1.27.0**). Choose the binary for the host running the command; firmware architecture does not matter because archive contents are never executed. Public clone/install instructions are in the [installation guide](docs/installation.md).

```sh
git clone https://github.com/Azhovan/rootfs-diff.git
cd rootfs-diff
./scripts/verify.sh
```

Build the command, then compare your baseline and candidate rootfs archives:

```sh
go build -o ./bin/rootfs-diff ./cmd/rootfs-diff
./bin/rootfs-diff baseline.tar candidate.tar.gz
./bin/rootfs-diff --format json baseline.tar candidate.tar.gz > report.json
./bin/rootfs-diff --policy policy.json baseline.tar candidate.tar.gz
```

Use the [sample policy](docs/cli.md#policy-format) for the last command, adapting it to your candidate. For a self-contained library example requiring no archive files:

```sh
go run ./examples/library
```

Put flags before both filenames. Exit **0** means the comparison and enabled checks passed, **1** means a configured gate failed, and **2** means invalid input or an operational failure. Exit 1 still produces a complete report. Treat output from exit 2 as incomplete.

## Scope

v0.1 accepts local tar and tar.gz files, reads without extraction, and reports explicit recorded data. It excludes timestamps, user/group names, xattrs, ACLs, capabilities and SELinux labels. Reports declare these exclusions and warn about encountered metadata that is not compared. Sparse archives and unsupported input formats fail. See [semantics and limits](docs/semantics.md).

This tool does not establish bootability, runtime correctness, OTA compatibility, CVE applicability, compliance or complete security equivalence. It does not unpack raw firmware, mount filesystems, attribute packages or run target binaries.

[Yocto buildhistory](https://docs.yoctoproject.org/dev/dev-manual/build-quality.html#build-history-image-information) already records package/image information and file permissions, ownership, sizes and symlinks. rootfs-diff overlaps with that file review while consuming standalone tar artifacts and applying explicit user gates across build systems. Keep buildhistory's package, dependency and build context alongside the artifact report. [diffoscope](https://diffoscope.org/) provides broader artifact comparisons.

The import path is `github.com/Azhovan/rootfs-diff`, package `rootfsdiff`. Development follows the [v0.1 contract](docs/v0.1-contract.md) and [delivery issue](https://github.com/Azhovan/rootfs-diff/issues/1).
